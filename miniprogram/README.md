# 朋友圈 · 微信小程序（纯展示版）

原生微信小程序，零构建。把 `pyq.ahxin.cn` 的朋友圈页面移植成**只读展示**：
没有评论、点赞、内容发布、登录、令牌和写接口，也不打开任何外部网页（链接只复制到剪贴板）。

与网页版是两套独立代码：网页版在项目根目录，本目录 `miniprogram/` 全是独立文件，互不影响。

**当前状态**：版本 `1.0.2`，代码已完成发布前全量回归，待在微信开发者工具里上传。

正文中的 Markdown 会降级成纯文本：标签隐藏，链接只保留文字、**不可点**。
转发给好友（`onShareAppMessage`）、复制链接（`wx.setClipboardData`）、页面跳转都是零申请基础能力；
真正需要资质的 `web-view` 业务域名和 `onShareTimeline` 已完全避开。

平台交互限制（不是权限）：小程序不能由代码指定好友或自动拉起好友列表，必须由用户点转发按钮后自己在微信里选。

## 数据来源（架构决策）

**已采用 A：复用现成的 Vercel Edge 只读代理。**

- `GET https://pyq.ahxin.cn/api/profile?user=ahxin` → 昵称 / 头像 / 简介
- `GET https://pyq.ahxin.cn/api/feed?pageSize=20&pageToken=...` → 公开信息流
- `GET https://pyq.ahxin.cn/api/memo?uid=<uid>` → 单条详情（分享卡片冷启动用）
- 附件与缩略图直连 `https://memos.ahxin.cn/file/...`（`?thumbnail=true` 走缩略图，预览与转发用缩略图，原图仅灯箱用）

`/api/feed` 是上游原样转发 + 边缘缓存，**作者过滤、归档过滤、可见性过滤都在小程序端 `utils/api.js` 做**，
与 `/api/memo` 的校验契约保持一致。选 A 的原因是后端零改动、无需新部署、Edge 已有 60s 缓存。

**备选 B：直连 `https://memos.ahxin.cn/api/memos`**，省掉一层代理，但要在小程序端自己做分页与缓存，
且 Memos 接口一旦变更需要同步改两端。仅在 A 的域名无法配置白名单时才考虑。

### 详情页数据来源（关键决策）

| | A（已采用） | B |
|---|---|---|
| 做法 | `GET /api/memo?uid=` 单独拉 | 列表页把整条数据缓存传给详情页 |
| 优点 | 好友从分享卡片冷启动也能打开；与网页版链接同源 | 少一次请求 |
| 代价 | 多一次轻量请求（Edge 已带 60s 缓存） | 冷启动没有数据，分享卡片打不开 |

分享链接仍是网页版地址 `https://pyq.ahxin.cn/?memo=<uid>`（只复制、不跳转）；
转发卡片 path 是 `/pages/detail/detail?uid=<uid>`，好友点开直达小程序内这条动态，返回时用 `reLaunch` 回落首页。

## 常用配置（`utils/config.js`）

| 想改什么 | 改哪里 |
|---|---|
| 换数据源域名 | `API_BASE`、`MEMOS_URL` |
| 换作者 / 兜底昵称 | `ADMIN_USER`、`NICKNAME` |
| 每页条数 | `PAGE_SIZE`（Memos 上限 50） |
| 显示正文 #标签 | `HIDE_TAGS: false` |
| 折叠行数 | `FOLD_LINES`（会注入 WXML 的 `-webkit-line-clamp`，WXSS 里保留 6 作兜底） |
| 换封面 | 替换 `images/cover.jpg`，或把 `COVER_URL` 改成外链（外链域名也要加白名单） |
| 封面竖图裁切 | `COVER_MODE`：`aspectFill` 铺满居中裁切（默认）/ `aspectFit` 完整显示 |
| 资料页两条链接 | `MEMOS_HOME`、`SITE_HOME` |
| 无图动态的转发封面 | `FALLBACK_SHARE_IMAGE`（默认站长头像 `memos.ahxin.cn/file/users/ahxin/avatar`，实测 `image/jpeg` 27KB） |
| 版本号 | `VERSION`（资料页底部展示） |
| 请求超时 / 重试 | `REQUEST_TIMEOUT`、`REQUEST_RETRY`、`RETRY_DELAY` |
